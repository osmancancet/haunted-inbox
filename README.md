# Haunted Inbox

A short browser game about spotting phishing emails. You work the night shift in
the mail room of a haunted manor. Letters arrive one by one: some are honest,
some are cursed. Deliver the honest ones, burn the rest.

Built with Kiro for Kiroween 2026, category **Costume Contest**.

## How to play

- Read the letter: sender, address, subject, body.
- Click a link to reveal where it really leads. Links are text only and never
  leave the game.
- **Hold to Candle**: by candlelight the ornate script turns into plain, widely
  spaced characters, so a zero no longer passes for an "o".
- Choose **Deliver** (legitimate) or **Burn** (phishing).
- A wrong call snuffs a candle. Three candles, ten letters, harder as the night
  goes on.
- After each letter you see the warning signs it carried and one practical
  lesson. The night ends with the signs you missed most.

Fully playable by keyboard. Motion is disabled when the system asks for reduced
motion. No accounts, no backend, no tracking; the best score stays in your
browser.

## Content

34 original letters (20 phishing, 14 legitimate) in three difficulty tiers and
eight warning signs: false urgency, spoofed sender, mismatched link, credential
request, too good to be true, unexpected attachment, authority pressure, and
unusual money or secrecy requests. The pool is built so that shortcuts fail:
legitimate letters carry links and deadlines too, and some phishing letters are
calm, polite and link-free. Schema tests in `src/content/letters.test.ts`
enforce these rules.

Every company, person and domain is invented.

## Run it

```
npm install
npm run dev      # local development
npm test         # unit and property-based tests
npm run build    # static site in dist/
```

Requires Node 20 or newer.

## Project layout

```
.kiro/           Kiro specs (requirements, design, tasks) and steering
src/game/        pure game logic and its tests
src/content/     letters, warning-sign definitions, schema tests
src/components/  React components
src/styles/      CSS variables and animations
```

## How Kiro was used

The requirements, design and task list in `.kiro/specs/haunted-inbox/` were
generated by Kiro from the steering files in `.kiro/steering/`, then revised
through Kiro as the content rules changed. Kiro implemented the task list
test-first, one commit per task: the seeded night generator, scoring, reducer,
letter schema tests and all React components. The visual theme, the content
review of the letters and a few follow-up fixes were done by hand afterwards.
